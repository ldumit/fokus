# F37-CodeQualityCleanup — Lessons

## Architect Lessons

- **A mining run's 100% survival came with a 41% downgrade rate — read the downgrades as the trust signal.** F36's skeptics refuted nothing (68/68) but lowered 28 severities; the main-session re-run of the HIGH evidence confirmed each. A bounded, evidence-first miner brief (≤12 findings, best first, command + excerpt) makes refutation rare; the skeptic's value moved to severity. (Evidence: [F37-CodeQualityCleanup] plan Context; F36 `mining/consolidated.md`)

- **Before adding `AsNoTracking`, audit for cross-query relationship fix-up, not only for mutate-and-save.** The F37 plan classified repository methods read-only by their callers' writes; Codex found three endpoints that take an entity from one query and read navigations a later tracked query filled in — `AsNoTracking` would silently empty them. A Sonnet reader probed the same class and missed it. Classify by "does any caller read a navigation this query did not Include", too. (Evidence: [F37-CodeQualityCleanup] review-critic.md R1-01)
- **A plan step whose correctness hinges on SQL translation needs a kept test in the suite, or the developer verifies it with a throwaway file run outside the runner.** Step 3's projection (`upper(TicketId)` grouping, Closed + Active filter) had no planned SQLite test; the developer wrote a scratch in-memory SQLite test, ran it by a raw command and deleted it, and that run plus three other raw `dotnet test` calls became done-check test slips (the test-entry gate logs but cannot deny a background subagent). When a step adds a query whose translation matters, plan a kept test for it (named file, runnable through `verify-run.js --files`). (Evidence: [F37-CodeQualityCleanup] done-check.md Check 1)

## Skill Gaps

- **Behaviour-preserving performance refactor across a feature area.** Step 5 changes the signature of a shared static helper used at 45 call sites in 12 files, plus 7 direct whole-list scans of the same shape to remove a quadratic scan. No project skill covers the shape: pin behaviour with characterisation tests first, introduce the faster structure, migrate every caller, keep the pins green. `boy-scout` is per-file and forbids cross-feature helpers; `analytics-computation-service` creates services, it does not refactor them. Candidate: a `characterise-then-refactor` skill. (Evidence: [F37-CodeQualityCleanup] plan Step 5)

## Developer Lessons

- **Plan accept greps written as `grep -rn ... src --include=*.cs` walk every `bin/` and `obj/` tree and overran the 120 s shell limit here.** Reproduce them with the Grep tool (same pattern, `glob: *.cs`), or add `--exclude-dir=bin --exclude-dir=obj`; the counts match (45 checker calls, 9 `Sprint not found.` files confirmed this way at analyze time). (Evidence: [F37-CodeQualityCleanup] developer analyze)
- **Scripted edits on this Windows checkout must preserve CRLF.** `core.autocrlf=true`, so working copies are CRLF while the index is LF; a Python `open(...).write(...)` with default newline handling silently rewrote five edited files to LF (git only warns). Use the Edit tool, or read with `newline=''` and write back with the file's own line ending; `git ls-files --eol {files}` shows the drift. (Evidence: [F37-CodeQualityCleanup] steps 1–2, step 7 — recurred: six repository files, restored with `sed 's/$/\r/'`)
- **A plan's "leave as is" list can name a structure whose only reader the same step rewrites.** Step 5's Scope kept `SprintSummaryService.ComputeMetrics`' case-insensitive grouping, but it fed only the checker whose signature the step changed, so it became dead and was removed (result unchanged: the checker re-filtered ordinally). When a refactor step changes a shared signature, check every "keep" item's readers first and record the outcome in the step's Decisions rather than preserving dead code or silently dropping it. (Evidence: [F37-CodeQualityCleanup] step 5)
- **"Accept active or closed" single-sprint branches in the analytics endpoints often load memberships, transitions and capacities for closed sprints only.** Before taking a target "from the membership-loaded list", check the target's state against what that list was loaded from: on Carry-Over, Bug Ratio and Leaderboard an active target is not in it, and its `Memberships` were empty even under tracking. (Evidence: [F37-CodeQualityCleanup] step 7)
- **"Validate the request before any shortcut" means every early return, including feature-off ones.** Step 6 put the sprint-id 404 before the empty-data shortcut but left the Xray-disabled 200 in front of it on the two QA endpoints, so a bad id still got 200 there; review caught it. When adding an input-existence check, list every `return` above it in `HandleAsync`, not only the one the plan names. (Evidence: [F37-CodeQualityCleanup] fix round 1)
- **A load failure and a mutation failure sharing one error ref lose each other.** Clearing the shared message at a mutation's start hid a still-standing load failure (UsersTab). Keep one message per load source, cleared only by that source's own successful reload; mutations get their own. (Evidence: [F37-CodeQualityCleanup] fix round 1)
