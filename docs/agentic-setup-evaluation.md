# Fokus Agentic Setup — Evaluation vs Industry State-of-the-Art

**Date:** 2026-05-13
**Scope:** Evaluation of the Fokus multi-agent pipeline (`.claude/agents/*` + `.claude/rules/*`) against current industry agentic coding setups.

## TL;DR

**This evaluation has two layers.**

**Layer 1 — against DEFAULTS and RESEARCH FRAMEWORKS** (Devin, ChatDev/MetaGPT, Claude Code's out-of-box guidance): Fokus scores 41/60 vs next-best 27/60. Top of the publicly-documented set against this bar.

**Layer 2 — against PUBLICLY-DOCUMENTED PRODUCTION SETUPS at real companies:** verdict is much narrower. **No directly comparable production setup is publicly documented.** Companies are placing divergent bets — Sourcegraph rejects sub-agents, Anthropic embraces parallel multi-agent, Shopify uses multi-experiment loops, PubNub uses a 3-role sequential pipeline, PostHog engineers are openly skeptical. Fokus is one credible bet among several. **No public evidence currently supports a "best in industry" claim in either direction.**

**Distinctive thesis (independent of ranking):** agents are allowed to be wrong, but never allowed to silently overrule the human or each other. No other reviewed setup articulates governance as a first-class topological concern.

**Strongest adversarial position to engage with:** Sourcegraph/Amp's "sub-agents are net negative" stance. Currently un-falsified by either side.

**Single biggest leverage upgrade available:** Wire a `Stop` or `PostToolUse` hook that runs the project build and blocks the reviewer handoff on failure.

## Production Peer Reality Check (Verified Public Documentation)

The Comparators section above measures Fokus against DEFAULTS and RESEARCH FRAMEWORKS. A separate, more honest comparison is against publicly-documented PRODUCTION setups at real companies. This is what's actually in the public record:

| Candidate | What's claimed | Verification status |
|---|---|---|
| **Anthropic** ("majority of code is now written by Claude Code") | Marketing page, unattributed | Same paragraph says "managing multiple agents in parallel" — explicitly multi-agent, not single. No named engineer cited, no scope defined |
| **Sourcegraph / Amp** (Quinn Slack + Thorsten Ball) | "Ship 15x/day"; "we just let the model rip" | Key claims live in paywalled podcast audio — cannot verbatim-verify on a public URL |
| **Cognition / Devin** ("⅓ of commits on our web app") | Verifiable URL | Unattributed; "web app" scope vague |
| **Tobi Lütke / Shopify Liquid** | Verifiable tweet, agent-produced commits merged into core product | **NOT a single-agent session** — `/autoresearch` ran ~120 automated experiments, 93 commits. Multi-experiment harness |
| **Mitchell Hashimoto / Ghostty** | "Having the one agent running is a good balance" | The specific shipped example (command palette) was generated by Gemini *chatbot*, not an agentic session |
| **PostHog** (Paul D'Ambra, Nick Best) | Named engineers, real product codebase, Claude Code on production code | Quotes are explicitly **negative**: "not actually very good software engineers"; "Claude Code writing Rust is a while loop that accelerates climate change" |
| **PubNub** (3-role pipeline: pm-spec → architect-review → implementer-tester) | Two engineering blog posts, named subagents, status flags | HIGH confidence — most credible production peer found. Strictly simpler than Fokus (no critic, no lessons loop, not language-agnostic) |

### Findings

1. **No verified clean example** of a serious company using single-agent sessions to ship core product code with named-engineer attribution.
2. **No verified clean example** of a serious company using a Fokus-equivalent multi-agent pipeline either. PubNub's 3-role setup is the closest production peer found; it is strictly simpler than Fokus.
3. **Public companies are placing divergent architectural bets.** No consensus exists.
4. **Public material is mostly marketing claims, paywalled podcasts, and anecdotes.** Detailed production architectures are not publicly documented at the level needed for cross-team comparison.

### Implication for the Score Card

The Score Card below now includes the two verified production peers (PubNub at 40%, Amp/Sourcegraph at 25%) alongside the defaults and research frameworks. **Both production peers score below Fokus** — but read that with the **Rubric Bias Disclosure** inside the Score Card. Amp's low score in particular reflects deliberate architectural choices (single-agent, anti-decomposition) that this rubric penalizes by design. The score card measures *alignment with Fokus's design philosophy*, not absolute industry rank.

### Rubric Bias Disclosure

**Critical caveat: this rubric is biased toward Fokus's design philosophy.** It weighs role decomposition, governance, pre-implementation discipline, and learning loops heavily. Setups that deliberately reject these dimensions score low — not because they fail at SWE, but because they're optimizing for *different* criteria.

The clearest case is **Amp/Sourcegraph**:

| What this rubric measures | What Amp values instead |
|---|---|
| Role decomposition (Fokus 5, Amp 0) | Single-agent simplicity |
| Multi-stage gates with severity (Fokus 5, Amp 1) | "Let the model rip" autonomy |
| Pre-implementation discipline (Fokus 5, Amp 1) | Iteration speed over upfront structure |
| Skill / pattern codification (Fokus 5, Amp 1) | Harness investment around the agent |
| Structured handoff schemas (Fokus 2, Amp 0) | No handoffs needed (single agent) |

**By Amp's implicit rubric, Fokus would likely score ~15/60** — Amp would penalize Fokus for context-passing overhead, structural rigidity, and absence of harness investment. So the Score Card measures *alignment with one design philosophy*, not absolute architectural quality.

## Dimensional Breakdown

### 1. Role decomposition

| | Approach |
|---|---|
| Devin | Single agent, internal phases (plan / execute / review). Not separately instantiated. |
| ChatDev / MetaGPT | 4–6 named roles (PM, architect, dev, QA, reviewer). |
| Claude Code | Composable. No prescribed roles. |
| **Fokus** | **6 roles** (PO, architect, critic, developer, reviewer, learner) + team lead orchestrator + solo for small work. |

**Verdict — Ahead of all three.** Fokus separates **spec authoring (PO) from planning (architect)** — ChatDev/MetaGPT collapse these. The **critic** as a dedicated document-quality role, separate from the code reviewer, is unique. Fokus reviews documents *and* code with different agents.

### 2. Communication topology

| | Approach |
|---|---|
| Devin | Monolithic — no inter-agent messaging |
| ChatDev | Chain (later DAGs in MacNet/puppeteer) with pairwise dialogue |
| MetaGPT | SOP-driven linear pipeline via structured artifacts |
| Claude Code | Hub-and-spoke recommended (orchestrator dispatches; sub-agents don't message each other) |
| **Fokus** | **Hub-and-spoke with active triage** — team lead inspects every message and intercepts those that contradict user decisions |

**Verdict — Ahead.** Claude Code recommends hub-and-spoke for technical reasons (scope isolation). Fokus uses it for *governance* — preventing silent user-decision reversal. The **User Decision Guardrail + team-lead triage** pairing is the most distinctive piece of this setup. No other reviewed system does this.

### 3. Quality gates

| | Approach |
|---|---|
| Devin | One automated PR-review pass |
| Aider | None |
| Codex | Optional `/review`, opt-in reviewer agent |
| ChatDev | Reviewer + Tester phase in chain |
| Claude Code | Hooks if wired |
| **Fokus** | **Two-stage review** (architect done-check + reviewer code-review) with **severity ratings** (CRITICAL / HIGH / MEDIUM / LOW) and **explicit cycle caps** (3 fix cycles → escalation) |

**Verdict — Significantly ahead.** Fokus is the only setup with severity-rated reviews + numbered cycle caps + escalation paths. Devin's review pass is binary. ChatDev's reviewer has no severity model. **Caveat:** no automated test-pass gate (Codex has this; Fokus relies on the reviewer to run the build manually per stack-rules).

### 4. Pre-implementation discipline

| | Approach |
|---|---|
| Devin | Editable upfront plan, then autonomous |
| ChatDev | Design phase via PM/CTO dialogue |
| MetaGPT | Structured PRD → Architecture → Tasks pipeline |
| Claude Code | Whatever you build |
| **Fokus** | **Spec → critic gate → plan → critic gate → developer.** Two independent quality gates before code is written. |

**Verdict — Ahead.** Most rigorous pre-implementation gating in the comparison set. MetaGPT comes closest (structured handoff documents) but doesn't have a critic role. **Risk:** can over-rotate for small features — which is why `solo` exists. The team/solo split is well-designed.

### 5. Cross-session learning loop

| | Approach |
|---|---|
| Devin | None (model-level improvement only) |
| Aider | None |
| Codex | AGENTS.md is static |
| ChatDev / MetaGPT | None (stateless frameworks) |
| Claude Code | "Dreaming" announced, not yet GA |
| **Fokus** | **lessons.md → learner agent → promotion to CLAUDE.md / agents / rules / skills** with recurrence threshold (2+) |

**Verdict — Ahead of everything actually shipping.** The only working cross-session learning loop in the comparison set. Manual trigger (user runs `be learner`), but real. Recurrence threshold prevents one-off noise from polluting system files. Anthropic's "Dreaming" is the announced equivalent but isn't GA. **Gap:** no telemetry on whether promoted lessons reduce recurrence; no detection of stale lessons.

### 6. Stack abstraction / portability

| | Approach |
|---|---|
| Devin / Codex | Closed products, language-aware internally |
| ChatDev / MetaGPT | LLM-prompted, language-flexible but no abstraction layer |
| Claude Code | CLAUDE.md + skills, project-defined |
| **Fokus** | **`stack-rules.md` as single-indirection rosetta stone** (after the May 2026 cleanup) |

**Verdict — Parity with Claude Code's design intent, executed.** Most public Claude Code setups in the wild have hardcoded language refs in agents — Fokus now doesn't (after collapsing developer/reviewer/solo imports to stack-rules only).

### 7. Human-in-the-loop policy

| | Approach |
|---|---|
| Devin | Upfront plan editing → autonomous |
| Codex | 7 configurable permission modes |
| ChatDev | Minimal — autopilot |
| Claude Code | "Trust trajectory" — auto-approve rate grows with session count (Anthropic data: 20% → 40%+ over 750+ sessions) |
| **Fokus** | **Hard rule: ≤11 plan steps + no open questions = auto-approve. Otherwise human approves.** Plus User Decision Guardrail. |

**Verdict — Different philosophy, not strictly ahead/behind.** Fokus's deterministic threshold is cruder than Anthropic's empirical trust trajectory but more *predictable* — you always know when it will ask. The User Decision Guardrail is unique. Trades adaptability for predictability.

### 8. Skill / pattern codification

| | Approach |
|---|---|
| Devin | None public |
| Aider | None |
| Codex | AGENTS.md |
| ChatDev / MetaGPT | Hardcoded role prompts |
| Claude Code | Skills (on-demand SKILL.md modules) |
| **Fokus** | **Skills with explicit authority hierarchy** — plans must reference a skill or justify inline detail; reviewer checks skill conformance |

**Verdict — Ahead within the Claude Code ecosystem.** Fokus uses Anthropic's Skills mechanism *more rigorously than Anthropic's own examples*. The "every plan step maps to a skill or justifies why not" rule is a strong forcing function against pattern drift.

## Distinctive Strengths

Where Fokus is genuinely state-of-the-art:

1. **Two-stage review with severity + cycle caps + escalation paths** — nobody else does this rigorously.
2. **Critic as dedicated document-quality role, separate from code reviewer** — unique role split.
3. **Team-lead triage with User Decision Guardrail** — the only governance-aware topology found in research.
4. **Real working cross-session learning loop** — beats announced-but-unshipped competitors.
5. **Pre-implementation discipline (spec critic + plan critic)** — most rigorous before-code gating in the comparison set.

## Adversarial Position: The Sourcegraph / Amp Anti-Sub-Agent Thesis

The single most architecturally substantive public critique of multi-agent pipelines comes from Quinn Slack (Sourcegraph CEO, lead of Amp):

> "Sub Agents are net negative now in our opinion." — Quinn Slack, Heavybit interview

The Amp thesis, distilled from publicly readable material:

- **Context-passing between agents loses fidelity.** A single agent with full task context beats a pipeline that hands off context across role boundaries.
- **Structure belongs in the harness, not in agent decomposition.** Sourcegraph's investment is in tooling around a single agent (unconstrained tool access, no token budget, iteration loops) — not in role separation.
- **Specialist agents miss holistic problems.** A reviewer agent looking only at code may miss issues a holistic agent would catch.

This is the most credible counter-argument to Fokus's design philosophy found in public material. Engaging with it honestly:

| Fokus's response | Strength of response |
|---|---|
| Fokus separates concerns to make each easier to verify | Real but partial — verifiability ≠ correctness. Amp's claim is that *correctness itself* degrades |
| Fokus has critic gates a holistic agent wouldn't have | The critic is also context-limited by the spec/plan it reads — the same loss-of-fidelity critique applies |
| Fokus's User Decision Guardrail prevents silent agent overrides | Governance feature, orthogonal to the agent-decomposition question. Could be implemented atop a single-agent setup |
| Empirical: track whether multi-agent gates catch real issues | Currently untested — Fokus has no telemetry to validate the multi-agent thesis |

**The honest reading:** Amp's critique has bite. Fokus's structure is a *bet* that role decomposition catches errors holistic single agents would miss. The bet has not been empirically validated by either side.

## Meaningful Gaps

Where SOTA is genuinely ahead, in priority order:

| Priority | Gap | What SOTA does | What Fokus could do |
|---|---|---|---|
| **HIGH** | No automated build/test gate | Codex runs tests as part of the loop and reports failures | Wire a `Stop` or `PostToolUse` hook that runs the project build and blocks the reviewer handoff if it fails |
| MEDIUM | No parallel task throughput | Devin / Codex queue 3–5 tasks in parallel sandboxes | Less critical for indie/small-team work, but a real ceiling on throughput |
| MEDIUM | No telemetry on learning loop | Anthropic publishes empirical auto-approve rates | Track which promoted lessons get hit; flag stale ones |
| LOW | No "Dreaming"-equivalent auto-curation | Anthropic's announced session-stop memory curation | Closing this needs a hook on session stop or a scheduled job |
| LOW | Heavyweight for small features | Codex's parallel-task model is lighter per task | `solo` mitigates this; the threshold is informal ("1–3 files") |
| LOW | No structured artifact schemas | MetaGPT enforces JSON SOPs at each handoff | Markdown templates work but are harder to machine-validate |
